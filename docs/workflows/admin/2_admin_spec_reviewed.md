# 기획 검토 의견서: admin

- 검토일: 2026-02-01
- 검토자: Gemini (AI)

## 1. 종합 의견
사용자의 요구사항이 명확하며, 특히 탭 기반의 상태 유지(Persistence)와 5개 제한 로직이 핵심입니다. 기존에 구현된 백엔드 API와 잘 연동될 수 있도록 프론트엔드 아키텍처를 세밀하게 설계해야 합니다.

## 2. 세부 검토 사항

### 2.1 UI/UX
- **사이드바**: '관리자 메뉴'를 최하단에 배치하기 위해 `Box`의 `position: absolute, bottom: 0` 또는 Flexbox의 `marginTop: 'auto'` 방식을 사용할 수 있습니다. Figma 디자인에 맞춰 다크모드 대응이 필요합니다.
- **탭 시스템**: Zustand를 사용하여 전역 상태로 탭 목록과 활성 탭 ID를 관리하면 탭 전환 시에도 상태 유지가 용이합니다.
- **5개 제한**: `addTab` 함수 내에서 `tabs.length`를 체크하여 `alert` 또는 `Snackbar`를 표시하는 로직이 필요합니다.

### 2.2 기능 로직
- **사용자 관리**: `userService.getUsers` 연동. 관리자 삭제 제한은 `Delete` 버튼의 `disabled` 속성을 `user.role === 'admin'` 조건으로 처리합니다.
- **패스워드 정책**: `passwordPolicyService` 연동. 폼 유효성 검사 필요.

## 3. 권장 사항
- 탭 내의 데이터 유실을 방지하기 위해 각 탭 컴포넌트 내부에서 `useEffect`와 Zustand를 적절히 활용하여 '작성 중' 상태를 보존해야 합니다.
- 사이드바 접힘/펼침 상태는 이미 `App.tsx`에서 관리 중이므로 이를 활용합니다.
