## 1. 개요

### 1.1 목적
관리자가 사용자 관리 화면에서 특정 사용자의 OTP(2FA)를 초기화(비활성화)할 수 있도록 한다.
OTP 기기 분실, 재등록 필요 등의 상황에서 관리자가 사용자의 OTP를 리셋할 수 있어야 한다.

### 1.2 배경
OTP를 한 번 활성화하면 현재 해제할 방법이 없다.
사용자가 OTP 기기를 분실하거나 재등록이 필요한 경우, 관리자가 OTP를 초기화해줘야 로그인이 가능해진다.
사용자 수정 모달에 상태(활성/비활성) 토글과 함께 OTP 초기화 기능이 필요하다.

### 1.3 범위

**포함:**
- 관리자가 사용자 수정 모달에서 OTP 비활성화 버튼 노출
- 백엔드 OTP 초기화 API 구현 (otp_enabled=false, otp_secret 등 초기화)
- 확인 다이얼로그 표시 후 실행
- i18n 처리 (ko/en/ja/cn)

**제외:**
- 사용자 본인의 OTP 해제 (별도 기능)
- OTP 로그 기록 (추후 고려)

## 2. 요구사항

### 2.1 기능 요구사항

#### 필수 기능 (Must Have)
1. 사용자 수정 모달에 OTP 초기화 버튼 추가 (OTP가 활성화된 사용자에게만 노출)
2. 초기화 클릭 시 확인 다이얼로그 표시
3. 확인 후 백엔드 API 호출하여 OTP 관련 필드 초기화
4. 성공/실패 스낵바 피드백

#### 선택 기능 (Should Have)
1. OTP 활성화 상태를 사용자 목록에서 시각적으로 표시 (아이콘/뱃지)

#### 향후 고려사항 (Nice to Have)
1. OTP 초기화 이력 로그 기록

### 2.2 비기능 요구사항

#### 보안
- admin 권한 사용자만 API 호출 가능
- 본인 계정 OTP는 이 API로 초기화 불가 (별도 처리)

## 3. 사용자 시나리오

### 3.1 주요 사용자
- 시스템 관리자 (admin 역할)

### 3.2 사용 시나리오

#### 시나리오 1: OTP 기기 분실 사용자 초기화
**사전 조건:**
- 관리자로 로그인된 상태
- 대상 사용자의 otp_enabled = true

**실행 단계:**
1. 사용자 관리 탭에서 대상 사용자의 수정 버튼 클릭
2. 사용자 수정 모달에서 "OTP 초기화" 버튼 클릭
3. 확인 다이얼로그에서 "확인" 클릭
4. 성공 스낵바 표시, 모달 내 OTP 상태 갱신

**기대 결과:**
- 사용자의 otp_enabled = false, otp_secret_enc = null, otp_backup_codes = [] 로 초기화
- 해당 사용자는 다음 로그인 시 OTP 없이 로그인 가능 (또는 재등록 요구)

**예외 상황:**
- 이미 OTP가 비활성화된 사용자에게는 버튼 미노출

## 4. 데이터 요구사항

### 4.1 필요한 데이터

| 데이터 항목 | 타입 | 필수 여부 | 설명 |
|------------|------|----------|------|
| user_id | string | 필수 | 초기화할 사용자 ID |

### 4.2 데이터 생성/수정/삭제
- 수정: cs_users 인덱스에서 otp_enabled=false, otp_secret_enc=null, otp_pending_secret_enc=null, otp_backup_codes=[], otp_enrolled_at=null 로 업데이트

---

## 5. API 요구사항

### 5.1 필요한 엔드포인트

#### API 1: OTP 초기화
- **Method:** POST
- **Path:** /api/v1/auth/otp/reset/{user_id}
- **설명:** 관리자가 특정 사용자의 OTP를 초기화
- **권한:** admin만 호출 가능
- **응답:**
  ```json
  { "message": "OTP가 초기화되었습니다." }
  ```

## 6. UI/UX 요구사항

### 6.1 화면 구성
- 위치: 사용자 수정 모달 (UserEditModal 또는 동등 컴포넌트)
- 버튼: "OTP 초기화" (color="warning" 또는 "error")
- 노출 조건: 해당 사용자의 otp_enabled === true 인 경우만

### 6.2 사용자 플로우
1. 수정 모달 열기 → OTP 활성 사용자면 초기화 버튼 노출
2. 버튼 클릭 → 확인 다이얼로그 ("이 사용자의 OTP를 초기화하시겠습니까?")
3. 확인 → API 호출 → 성공 스낵바

## 7. 제약사항 및 고려사항
