## 📌 변경 이력 요약

### 초안 대비 주요 변경사항
1. **레이아웃 고정:** 복잡한 드래그 앤 드롭 대신 Phase 1에서는 고정된 그리드 레이아웃을 사용하기로 확정.
2. **데이터 갱신 방식:** WebSocket 대신 클라이언트 측 Polling(30초 주기 등) 방식으로 단순화.
3. **OpenSearch 연동 구체화:** OpenSearch의 집계(Aggregation) API를 사용하여 통계 데이터를 가져오는 구조 정의.

### Claude 검토 반영 사항
- 반영한 제안:
  - 위젯별 데이터 소스 정의 (OpenSearch 인덱스 활용)
  - 차트 데이터 Pydantic 스키마 정의 제안 수용
- 반영하지 않은 제안 및 이유:
  - 대시보드 레이아웃 저장 기능 (Phase 2로 연기하여 핵심 시각화에 집중)

## 1. 개요

### 1.1 목적
SIEM 시스템의 핵심 정보를 한눈에 파악할 수 있는 시각화 대시보드 구현.

### 1.2 배경
사용자가 수집된 로그 현황, 보안 위협 및 시스템 상태를 직관적으로 모니터링할 수 있는 중심 페이지가 필요함.

### 1.3 범위

**포함:**
- 상단 컨트롤 바 (기간 선택, 필터, 수동 새로고침)
- 통계 차트 (OpenSearch Aggregation 기반 막대 차트)
- 로그 요약 그리드 (최근 로그 목록)
- MUI 기반 다크 모드 지원 레이아웃

**제외:**
- 커스텀 위젯 편집/이동 기능
- 실시간 WebSocket 스트리밍 (Polling으로 대체)

## 2. 요구사항

### 2.1 기능 요구사항

#### 필수 기능 (Must Have)
1. **기간 필터링:** 15분, 1시간, 24시간 등 전체 대시보드 데이터를 조절하는 글로벌 필터.
2. **로그 빈도 차트:** 시간대별 발생 로그 수를 시각화하는 막대 차트 (`bar_chart.svg` 디자인 적용).
3. **자동 갱신:** 설정된 주기(기본 30초)마다 API 재호출을 통한 데이터 갱신.

#### 선택 기능 (Should Have)
1. **심각도별 분류:** 로그 심각도(Severity)에 따른 차트 색상 구분.
2. **수동 새로고침 버튼:** 즉시 데이터를 갱신할 수 있는 버튼.

#### 향후 고려사항 (Nice to Have)
1. **위젯 리사이징:** 사용자가 위젯 크기를 조절하는 기능.
2. **PDF 내보내기:** 대시보드 현재 뷰를 리포트로 출력.

## 5. API 명세 (확정)

### 5.1 엔드포인트 목록

#### API 1: 대시보드 통계 조회
- **Method:** GET
- **Path:** `/api/v1/dashboard/stats`
- **인증:** Required
- **설명:** 대시보드 차트 및 위젯에 필요한 집계 데이터를 한 번에 반환.

**성공 응답 (200):**
```json
{
  "charts": {
    "log_histogram": [
      {"timestamp": "2026-02-03T10:00:00Z", "count": 150},
      {"timestamp": "2026-02-03T11:00:00Z", "count": 200}
    ],
    "severity_distribution": {
      "info": 1200,
      "warning": 45,
      "critical": 3
    }
  }
}
```
