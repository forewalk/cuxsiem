# [검토보고서] 계정 신청 기능 (Account Application)

## 1. 검토 개요
- **대상 문서**: `1_account_spec.md`
- **검토 목적**: 기술적 실현 가능성 확인 및 기존 코드와의 정합성 검토

## 2. 검토 결과 요약
- **기술적 타당성**: 매우 높음. 기존 `UserManagementTab`의 모달 로직과 `passwordPolicyService`를 활용하여 효율적으로 구현 가능함.
- **요구사항 충족**: 역할(사용자), 상태(비활성) 고정 및 비밀번호 정책 적용 요구사항 모두 구현 가능함.

## 3. 상세 검토 내용

### 3.1 프론트엔드 구현 (React/MUI)
- **모달 재사용**: `UserManagementTab.tsx`의 `Dialog` 구조를 참고하여 `AccountApplyModal.tsx`를 생성함. 이미지 `a1.png`와 유사한 스타일을 유지하되, 요구사항대로 '역할'과 '상태' 필드는 UI에서 제거함.
- **비밀번호 검증**: `passwordPolicyService.getPolicy()`를 호출하여 현재 시스템 정책(최소 길이, 대소문자, 특수문자 등)을 가져온 후, 사용자가 입력하는 동안 각 조건을 충족하는지 시각적으로 표시(예: 체크박스 또는 텍스트 색상 변경)하는 로직 추가 제안.
- **로그인 연동**: `Login.tsx` 컴포넌트의 하단(로그인 버튼 아래 또는 링크 섹션)에 `t('applyAccount')` 텍스트를 가진 링크를 추가함.

### 3.2 백엔드 구현 (FastAPI)
- **API 신설**: 인증되지 않은 사용자(Anonymous)가 접근 가능한 `POST /api/v1/accounts/apply` 엔드포인트가 필요함.
- **보안 로직**: 백엔드에서 `role`은 무조건 `user`로, `is_active`는 무조건 `false`로 강제 설정하여 클라이언트의 조작 방지.
- **기존 서비스 활용**: `UserService.create_user` 로직을 재사용하되, 계정 신청 전용 유효성 검사 로직 적용.

## 4. 제안 및 개선 사항
- **다국어 지원**: `ko.json`, `en.json`, `ja.json`에 계정 신청 관련 텍스트(제목, 버튼명, 신청 완료 메시지 등) 추가 필요.
- **신청 완료 알림**: 신청 성공 후 "관리자의 승인이 필요합니다"라는 안내를 담은 성공 알림(Snackbar 또는 별도 Alert) 표시 필요.

## 5. 결론
기획 내용이 기술적으로 타당하며, 기존 시스템의 아키텍처와 잘 부합함. 검토 의견을 반영하여 3단계(기획 확정)로 진행을 권고함.
