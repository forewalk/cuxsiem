# 알림 규칙 관리 (Notification Rule Management) 기능 기획서

**작성일:** 2026-02-11
**작성자:** Gemini
**버전:** 1.0
**상태:** 초안

---

## 1. 개요

### 1.1 목적
사용자가 로그 데이터를 기반으로 탐지 규칙을 설정하고, 탐지 시 다양한 채널(Slack, Webhook, Email)로 알림을 받을 수 있도록 규칙을 관리(생성, 조회, 수정, 삭제)하는 기능을 제공한다.

### 1.2 배경
기존에 알림 센터의 사이드바 메뉴와 목록 UI의 뼈대는 구현되었으나, 실제 규칙을 생성하거나 수정하는 기능이 '준비 중'으로 남아있어 이를 완성할 필요가 있음.

### 1.3 범위
**포함:**
- 알림 규칙 목록 조회 및 검색
- 알림 규칙 생성 (Add Rule Form)
- 알림 규칙 수정 (Edit Rule Form)
- 알림 규칙 삭제 및 상태(활성/비활성) 토글
- 알림 채널(Slack, Webhook, Email) 설정 UI

**제외:**
- 실제 알림 발송 엔진 (백엔드 워커 로직)
- 알림 내역(History) 상세 조회 기능 (별도 작업)

## 2. 요구사항

### 2.1 기능 요구사항

#### 필수 기능 (Must Have)
1. **규칙 목록 표시:** 이름, 위험도, 실행 주기, 상태, 최근 발생 시간 등을 테이블로 표시.
2. **규칙 생성/수정 폼:** 다이얼로그 형태로 제공하며, 필수 필드(이름, 인덱스, 쿼리, 위험도 등) 입력 검증.
3. **위험도 설정:** Critical, High, Medium, Low, Info 중 선택.
4. **실행 및 범위 설정:** 탐지 주기(분)와 데이터 조회 범위(분) 설정. (조회 범위 >= 탐지 주기)
5. **탐지 조건 설정:** OpenSearch DSL 쿼리 형식을 입력할 수 있는 텍스트 영역 또는 에디터 제공.
6. **채널 설정:** Slack(채널, Webhook URL), Webhook(URL, Method, Header), Email(수신자) 추가 기능.
7. **상태 관리:** 규칙 활성화/비활성화 전환.

#### 선택 기능 (Should Have)
1. **중복 제거 설정:** 중복 제거 TTL 및 키 템플릿 설정 기능.
2. **테스트 발송:** 설정된 채널로 테스트 메시지를 보내는 기능.

## 3. 사용자 시나리오

### 3.1 주요 사용자
- 시스템 관리자 (Admin): 보안 정책에 따른 탐지 규칙을 설정하고 알림을 수신하고자 함.

### 3.2 사용 시나리오

#### 시나리오 1: 새로운 알림 규칙 생성
**사전 조건:**
- 관리자 계정으로 로그인하여 '알림 규칙 목록' 탭에 진입.

**실행 단계:**
1. '규칙 추가' 버튼을 클릭한다.
2. 규칙 이름, 대상 인덱스, 위험도, 주기를 입력한다.
3. 탐지 조건(DSL 쿼리)을 입력한다.
4. 알림 채널(예: Slack)을 추가하고 정보를 입력한다.
5. '저장' 버튼을 클릭한다.

**기대 결과:**
- 새로운 규칙이 목록에 추가되고, 백엔드에 저장된다.

## 4. 데이터 요구사항

### 4.1 필요한 데이터

| 데이터 항목 | 타입 | 필수 여부 | 설명 |
|------------|------|----------|------|
| name | string | 필수 | 규칙 이름 |
| target_index | string | 필수 | OpenSearch 인덱스명 |
| severity | string | 필수 | 위험도 (Critical~Info) |
| interval_min | integer | 필수 | 탐지 주기 (분) |
| window_min | integer | 필수 | 데이터 범위 (분) |
| condition_config | object | 필수 | DSL 쿼리 등 설정 |
| channels | object | 선택 | Slack, Webhook, Email 설정 |
| is_active | boolean | 필수 | 활성화 여부 |

## 5. API 요구사항

### 5.1 필요한 엔드포인트
- GET /api/v1/notifications/rules: 목록 조회
- POST /api/v1/notifications/rules: 생성
- GET /api/v1/notifications/rules/{id}: 단건 조회
- PUT /api/v1/notifications/rules/{id}: 수정
- DELETE /api/v1/notifications/rules/{id}: 삭제

### 6.1 화면 구성
