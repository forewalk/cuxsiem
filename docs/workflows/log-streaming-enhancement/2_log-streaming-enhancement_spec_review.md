# 기획서 검토: 로그 스트리밍 기능 강화

## 1. 분석 및 이해
- **목표**: 사용자가 로그 필드를 동적으로 선택하고, 상세 정보에서 즉시 필터링할 수 있는 UI 구현.
- **핵심 엔티티**: `LogStreamingTab`, `LogDetailPanel`, `LogStreamControlBar`.
- **데이터 흐름**: 
  - `logs` 데이터 분석 -> 사용 가능한 필드 추출 -> 필드 선택기 UI 표시.
  - 상세 패널 클릭 -> `searchQuery` 문자열 업데이트 -> `LogStreamingTab` 리렌더링 및 필터링 로그 표시.

## 2. 검토 항목
- [x] **기술적 타당성**: React State와 MUI Popover를 활용하여 충분히 구현 가능함.
- [x] **아키텍처 정합성**: 기존 `LogStreamingTab`의 구조를 유지하며 컴포넌트 간 통신(Callback)을 통해 구현 가능.
- [x] **UI/UX 일관성**: MUI 아이콘과 테마 색상을 활용하여 기존 Kibana 스타일의 디자인 유지.
- [x] **성능 고려**: `flattenObject`와 필드 추출 로직이 로그가 많아질 때 느려질 수 있으므로 `useMemo` 활용 필요.

## 3. 보완 사항 및 질문
- **필드 저장**: 사용자가 선택한 필드를 새로고침 후에도 유지할 것인가? (우선순위 낮음, 현재는 세션 내 유지로 구현)
- **필터 삭제**: 검색창에서 개별 조건을 삭제하는 기능은 이미 존재하므로 추가 조건 결합 방식만 잘 정의하면 됨.
- **필드 추출**: 모든 로그를 순회하며 필드를 찾을 것인지, 아니면 최근 N개의 샘플만 볼 것인지? (최근 수집된 로그 기준 추출 권장)

## 4. 최종 의견
