# 로그 스트리밍 기능 기술 문서

## 1. 개요
이 문서는 OpenSearch의 `activities` 인덱스 데이터를 실시간으로 모니터링하기 위한 로그 스트리밍 기능의 기술적 구현 명세를 설명합니다.

## 2. 아키텍처

### 2.1 백엔드 (FastAPI)
- **Endpoints:** 
  - `GET /api/v1/logs/stream`: 로그 스트리밍 데이터 조회
  - `GET /api/v1/logs/indices`: 사용 가능한 인덱스 목록 조회
- **핵심 기술 로직:**
  - **타임스탬프 호환성:** OpenSearch의 여러 인덱스가 서로 다른 타임스탬프 필드명(`@timestamp`, `timestamp`)을 사용할 수 있으므로, `bool.should` 쿼리와 `unmapped_type: "date"` 정렬 옵션을 사용하여 모든 인덱스에 대해 안정적인 조회를 보장합니다.
  - **검색 쿼리 지원:** `q` 파라미터를 통해 Lucene 쿼리 문법을 지원하며, 기본 검색 필드를 `message`로 설정하여 사용자가 직관적으로 검색할 수 있도록 합니다.
  - **시간 범위 필터링:** `from_time`과 `to_time`을 통해 상대 시간(예: `now-15m`) 및 절대 시간(ISO 8601) 검색을 모두 지원합니다.

### 2.2 프론트엔드 (React + MUI)
- **컴포넌트:** `LogStreamingTab`
- **외부 컴포넌트 연동:**
  - `ControlBar`: 대시보드에서 사용하는 공통 컨트롤바를 통합하여 시간 범위, 인덱스 선택, 검색 기능을 일관성 있게 제공합니다.
- **상태 관리:**
  - `logs`: 현재 화면에 표시 중인 로그 배열 (최대 1,000개).
  - `isPaused`: 폴링 일시 정지 여부.
  - `autoScroll`: 새 로그 유입 시 최하단 이동 여부.
  - `selectedIndex`: 현재 선택된 OpenSearch 인덱스 또는 와일드카드(`*`).
- **주요 로직:**
  - `setInterval`을 이용해 10초마다 백엔드 API를 호출합니다.
  - `useRef`를 사용하여 마지막 수신 로그의 타임스탬프(`lastTimestampRef`)를 추적하고, 중복 수신 방지를 위해 `_id` 필드를 대조합니다.
  - **메시지 줄 제한:** 성능 및 가독성을 위해 CSS의 `-webkit-line-clamp: 5` 속성을 사용하여 메시지를 최대 5줄로 제한합니다.

## 3. UI/UX 디자인
- **테마:** 다크 모드 기반의 터미널 스타일 배경 (#1e1e1e).
- **폰트:** Monospace 계열을 사용하여 로그 가독성을 확보했습니다.
- **레이아웃:** 너비가 고정된 타임스탬프 및 인덱스 열을 제공하고, 메시지 열은 가변적으로 확장되어 화면 공간을 효율적으로 활용합니다.
- **자동 스크롤:** 사용자가 현재 위치를 유지하고자 할 때(위로 스크롤 시) 자동 스크롤을 감지하여 해제하는 스마트 스크롤 기능을 포함합니다.
- **상세 보기:** 개별 로그 행을 클릭하면 오른쪽에 JSON 형태의 상세 정보를 확인할 수 있는 패널이 나타납니다.

## 4. 설정 및 환경변수
- OpenSearch 연결 정보는 백엔드 `.env` 설정을 따릅니다.
- 프론트엔드 폴링 주기는 `POLL_INTERVAL` 상수로 조절 가능합니다. (기본 10,000ms)
- 최대 로그 유지 개수는 `MAX_LOGS` 상수로 정의되어 있습니다. (기본 1,000개)
